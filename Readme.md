## Установка

1. В корне приложения создаем конфигурационный файл Laravel:

```bash
cp .env.example .env
```

2. Разворачиваем контейнеры приложения через Docker compose:

```bash
docker-compose up --build -d
```

3. Одной командой запускаем генерацию ключа Laravel и проводим миграции с сидерами:

```bash
make run
```

## Стек технологий:

- Язык: PHP 8.5
- Фреймворк: Laravel 13.x
- Сервер: Nginx
- База данных: PostgreSQL 18.4
- Очереди: Redis + Horizon
- Контейнеризация: Docker, Docker compose
- Тестирование: PHPUnit
- Статический анализ: PHPStan (Уровень 5)
- Code style fixer: pint

## Архитектурное решение:

Архитектурное решение - монолит с элементами SOA. Для простоты
разработки и развертывания проект реализован как монолитное приложение — весь код находится в одном репозитории и разворачивается как единое целое через Docker Compose. При этом сам код организован по принципу `Service-Oriented Architecture (SOA)`:
- Сервисы: основная бизнес-логика вынесена в отдельные сервисы
- DTO: четкая типизация данных между слоями
- Job: асинхронная обработка запроса (очереди)

В проекте использованы паттерны программирования Стратегия (EmailChannel, TelegramChannel), Фабричный метод (ChannelFactory), Dependency injection.

## Гарантия отправки уведомлений:

- При отправке уведомления с ошибкой сервис делает еще 2 попытки (время задержки между попытками 10 сек.). После третьей неудачной попытки статус уведомления меняется на `error`, а сама задача сохраняется в таблице `failed_jobs`
- Для генерации отчетов все то же самое, только статус после трейтьей неудачной попытки меняется на `failed`

В Horizon админитратор может отследить все очереди, завершившиеся с ошибкой, в разделе Failed Jobs, и вручную их перезапустить.

## Как улучшить в продакшене:

- Использовать Supervisor для автоматического поднятия контейнера с очередями, если он упадет.
  Можно добавить автоматический перезапуск раз в день всех очередей из таблицы `failed_jobs`, чтобы не делать это вручную.
- Вместо Redis + Horizon можно использовать брокер сообщений RabbitMQ для 100% гарантии доставки уведомлений.
- Добавить CI/CD для проверки Phpstan и pint перед каждым merge_request.
