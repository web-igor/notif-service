# Сервис уведомлений Notif-service через email и Telegram с гарантией доставки и генерацией отчетов (тестовый проект)

## Запуск (все команды запускаются в корне приложения):

1. Создаем конфигурационный файл Laravel:
`cp .env.example .env`

2. Разворачиваем контейнеры приложения через Docker compose:
`docker-compose up --build -d`

3. Одной командой запускаем генерацию ключа Laravel и проводим миграции с сидерами (добавляются пользователи и связанные уведомления):
`make run`

## Архитектурное решение: Монолит с элементами SOA
Проект реализован как монолитное приложение — весь код находится в одном репозитории и 
разворачивается как единое целое через Docker Compose. Это решение принято для простоты 
разработки и развертывания.

Сам код организован по принципу `Service-Oriented Architecture (SOA)`:
1. `Сервисы:` основная бизнес-логика вынесена в отдельные сервисы:
  - `NotificationService` - создание и отправка уведомлений
  - `ReportService` - генерация отчетов
2. `DTO:` четкая типизация данных между слоями
3. `Job:` асинхронная обработка запроса (очереди):
   - `SendNotificationJob` - отправка уведомления
   - `GenerateReportJob` - генерация отчета

## Как реализована гарантия отправки уведомления и генерации отчета:
1. При отправке уведомления с ошибкой сервис делает еще 2 попытки (время задержки между попытками - 10 сек.).
   После третьей неудачной попытки статус уведомления меняется на `error`, а сама задача сохраняется в таблице `failed_jobs`
2. Для генерации отчетов все то же самое, только статус после трейтьей неудачной попытки меняется на `failed`

В Horizon админитратор может отследить все очереди, завершившиеся с ошибкой, в разделе Failed Jobs, и вручную их перезапустить.

## Что использовать в продакшене:
1. Supervisor для автоматического поднятия контейнера с очередями, если он упадет. 
Можно добавить автоматический перезапуск раз в день всех очередей из таблицы `failed_jobs`, чтобы не делать это вручную.
2. Вместо  Redis + Horizon можно использовать брокер сообщений RabbitMQ для 100% гарантии доставки уведомлений.
3. CI/CD для проверки Phpstan и pint перед merge_request.
